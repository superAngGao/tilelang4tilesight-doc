日期：2026-09-17。实现说明基线：适配器 `b15b4ac`，TileSight `48e4158459bee5df830ae4ab7dda541edaa3dc4d`。

本文用于对外技术说明与交付附件导航，将协议附件中性能分析工具的功能、问题类型及指标要求，映射到本仓库的技术路线和所需报告证据。需求采用技术性摘述，不附协议原文、商务内容或内部测试数据。

**这是功能对照索引，不是验收通过证明。** 有接口、能生成报告和在指定测例上验证准确是三件不同的事。最终交付仍需补充对应版本的用例、实际结果和验收记录。

## 1. 范围和阅读入口

当前路线面向 NVIDIA H200 上单个 TileLang kernel，支持模型分析、独立运行时报告和联合分析。Op 仅用于组织测例；不能把 Op.forward 中多个 kernel 和数据准备的总时间当作目标 kernel 时间。

本索引不证明协议整体完成，不覆盖其他厂商适配、算子库、编译器和错误调试工具的交付结论。

## 2. 功能要求对照：协议附件 1.1

| 功能要求 | 我们的解法 | 报告或交付证据 | 当前边界 |
|---|---|---|---|
| 编译期 tile 元数据与 pipeline 提取 | 从 builder 取得高层 TIR，规范化操作、存储、值、执行域和访问；推导工作量、依赖与跨轮关系 | 操作 ID、来源、形状、dtype、读写、操作–Phase 映射、Region 和依赖图 | 模型路径不读取 CUDA/PTX/SASS；未知结构或缺少必要输入时明确报告，不假定零工作 |
| Tile 性能建模及可查询接口 | 将工作量和依赖转成 TileSight 输入，使用官方成本、流水和完整时间分析 | Phase 完成时间、资源服务时间、II、关键约束、工作单元和 kernel 时间；Python/CLI 使用说明 | 时间是模型结果；Phase 可以合并或拆分，不能任意给每个 tile 操作分配独立耗时 |
| 缓存行为预测 | 从访问身份、有效范围、grid 和遍历构造 CacheProblem；将命中率和分层流量映射到阶段需求 | 缓存配置、访问映射、命中率分母、分层字节、采样与近似说明 | 规则访问模型，不是任意地址序列或精确运行时时序模拟；SMEM 带宽分析不等于 bank-conflict 预测 |
| 运行期 tile-aware 采集与代价关联 | NCU 采集精确目标 kernel；用身份和访问映射将可对应的执行条件、访存需求交给模型 | 原始计数、单位、采集范围、目标身份、采用的反馈及分配记录 | **部分覆盖**：kernel 级观测可关联或按模型需求比例分配，但不能由此声称获得直接实测的 tile/Phase 耗时、II 或时间线 |
| 离线分析与报告 | 从已生成结果输出表格、HTML；已有模型排程可导出 Perfetto 格式 | 操作、阶段、资源、访存、缓存、完整时间及诊断视图 | 时间线必须来自已有调度记录；缺起点不能通过累加耗时编造。当前 Perfetto 出口面向模型排程，不是通用 NCU trace 导出器 |

运行时组件已经存在，因此不再沿用旧说明中的“运行时路径全部待实现”。但运行时程序可用，也不等于协议中真实 tile 级采集的全部能力已经具备。

## 3. 六类问题对照：协议附件 1.2

问题定义见 [README](../README.md)。下表说明两条路径分别提供什么，以及联合分析不能越过的边界。

| 问题 | 模型路径提供 | 运行时/联合路径提供 | 不能据此宣称 |
|---|---|---|---|
| Tile pipeline 瓶颈 | 阶段依赖、资源需求、关键路径和周期约束，解释计算、搬运或同步限制 | 资源利用、stall 等压力线索；合格执行条件和流量回灌后重新分析 | NCU 汇总利用率或 stall 直接定位到某一 Phase 的实测耗时 |
| 跨层级搬运异常 | 各访问和阶段的分层字节、搬运需求和计量范围 | 同口径 L2/DRAM 流量比较、普通访存效率、local-memory 等观测 | 全部 local-memory 都是 spill，或所有额外流量都已有准确阶段归属 |
| 缓存利用异常 | 命中率及缓存流量预测，保留层级和统计范围 | 观测命中计数、分母和阈值；符合条件的流量或派生需求可用于联合分析 | NCU L1/TEX 等同于模型 L1.5；任何命中率都能直接替换全部 Phase 的缓存属性 |
| 计算–IO 重叠失败 | 已支持 DAG 的阶段起点、完成区间、资源区间和依赖，展示模型允许的重叠 | 汇总计数作为线索；联合重算后展示新的模型排程 | 已直接测得 tile 级重叠时间线；仅凭两类资源利用率即可重建真实流水 |
| 负载不均 | grid、工作次数、源层驻留假设、波次及尾波；已解析的控制和参与范围 | 理论容量、实际 occupancy、可用的 SM 分布统计作为线索 | 已还原所有 CTA/cluster 的执行分配，或精确定位任意数据相关分支的不均衡 |
| 模型预测偏差 | 纯模型时间与输入、中间工作量、依赖和上下文 | 合格的 NCU/CUPTI kernel 时间对比，以及联合预测变化 | 所有差异都是解析错误，或联合输入必然使误差变小 |

### 3.1 诊断结论的用语

- **发现问题**：明确指出满足了什么判断条件，附范围、数值、阈值和来源。模型判断仍应标为模型判断。
- **未发现问题**：在已有有效证据和指定检查范围内未触发规则，不代表整个 kernel 没有性能问题。
- **证据不足或未评估**：缺少所需信息，不能转写为“正常”。
- 利用率、stall 等间接证据应称为线索；有一个问题类别的报告栏目，不等于已经实现该类别全部诊断能力。

## 4. 粒度与输出对照：协议附件 1.3

| 要求的粒度或形式 | 对应产物 | 阅读注意事项 |
|---|---|---|
| Tile 操作代价及利用率相关信息 | 操作元数据、操作–Phase 映射、关联的模型成本和资源需求 | 一对一才可直接对应单阶段；合并/拆分要展示映射，不伪造独立耗时。资源 service time 不是实测利用率 |
| Tile pipeline 结构和关键路径 | 阶段、依赖、跨轮距离、缓冲容量、II 及已有排程 | II 是启动间隔，不是一次循环完成时间或整个 kernel latency；非周期结构不应伪造 II |
| 硬件层级负载和流量 | 资源需求、分层字节、grid/驻留/尾波及运行时统计 | 资源服务时间之和不是经过时间；必须保留单阶段、单轮或全 kernel 的范围 |
| 缓存层级命中率和流量 | 模型缓存访问结果、NCU 计数、采用的反馈 | 区分请求与字节、读写方向、条件命中率与全部请求比例 |
| Kernel 与 session 元数据 | 源码/构建/输入身份、版本、设备、采集和运行标识 | session 可组织多份记录，但当前基本分析对象仍是单 kernel，不声称自动推导跨 kernel 流水或缓存延续 |
| 热点、层级视图、时间线 | HTML、CSV、结构化 JSON 和模型 Perfetto 输出 | 模型与 runtime 使用各自结果对象；渲染不重新计算成本，不将模型时间线标为实测 |
| 仅建模、仅采集及交叉校准 | 纯模型、独立 NCU 报告、联合预测并列 | 当前“交叉校准”指采用合格观测后重算，不表示自动重新标定官方成本模型 |

## 5. 联合分析采用哪些数据

详细流程见[两条路径解法第 7 节](model-runtime-solution-cn.md)。快速边界如下：

| 数据 | 当前用途 |
|---|---|
| 目标身份、grid/block/cluster、设备和 SM 数 | 核对是否为相同分析对象与执行上下文 |
| 理论 CTA 容量及寄存器/SMEM 分配证据 | 以符合合同的容量限制替换源层驻留估计；不是把 achieved occupancy 直接换成驻留数 |
| 可对应的 L2/DRAM 分方向流量；受支持的命中计数派生需求 | 按同口径原需求和完整发生次数分配，替换对应资源需求并检查总量守恒 |
| kernel duration、利用率、stall、spill/local、bank conflict 等 | 时间对比或诊断；未有可靠阶段映射和成本接口的观测仅报告，不强行反馈 |

同一资源、方向和范围只采用一个来源。原始观测、派生值、模型分配值和实际采用值分别保存。kernel 实测时间不能先按比例分成 Phase 成本，再作为预测输入。

## 6. 用于交付时还要附什么

本文可作为附件目录页。每次交付应另外绑定以下材料，而不是仅提交这张对照表：

1. **版本和范围**：适配器、TileSight、TileLang、测例源码版本，设备与已支持/未支持范围。
2. **可复现测例**：kernel 路径和函数、形状、dtype、构建配置、必要输入值或生成方法；模型与实测必须对应同一目标。
3. **模型产物**：语义和阶段映射、工作量、依赖、缓存输入/结果、Timing、执行环境与完整时间。
4. **运行时产物**：原始 NCU 报告、采集命令和条件、结构化观测；使用 CUPTI 对比时另附其样本及统计。
5. **联合产物**：采用和拒绝反馈的明细、分配规则及纯模型/实测/联合预测对照。
6. **呈现与验证**：JSON、表格、HTML、可用的 Perfetto 文件，以及功能测试、偏差分析和未解决问题清单。

纯模型证据、硬件观测和归因假设都应可追溯。公开仓库用于技术导航；未经另行确认，不附协议原件、内部地址、设备标识或原始采集文件。
